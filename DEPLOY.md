# Как выложить сайт в интернет бесплатно

Рекомендуемый вариант — **Render**: он умеет запускать обычный Node.js-сервер,
даёт HTTPS-ссылку и не требует банковской карты на бесплатном плане.

Понадобятся два бесплатных аккаунта:

1. **GitHub** — там будет лежать код.
2. **Render** — он запустит сайт и выдаст ссылку.

---

## Шаг 1. Создайте пустой репозиторий на GitHub

1. Войдите на [github.com](https://github.com) (или зарегистрируйтесь).
2. Нажмите **New repository**.
3. Имя: `kpk-schedule`.
4. Выберите **Private** или **Public** — для Render подойдёт любой.
5. **Не** ставьте галочки «Add README», «Add .gitignore», «Choose a license» —
   репозиторий должен быть пустым.
6. Нажмите **Create repository** и скопируйте адрес вида
   `https://github.com/ваш-логин/kpk-schedule.git`.

## Шаг 2. Отправьте проект на GitHub

Проект уже инициализирован как git-репозиторий. Откройте PowerShell:

```powershell
cd E:\DeeepSeek\college-schedule

git remote add origin https://github.com/ВАШ-ЛОГИН/kpk-schedule.git
git push -u origin main
```

Если Git попросит пароль:

- проще всего выбрать **«Sign in with your browser»** — откроется GitHub,
  и вход подтвердится автоматически;
- либо создайте **Personal Access Token** на GitHub
  (Settings → Developer settings → Personal access tokens → Tokens (classic),
  права `repo`) и вставьте его вместо пароля.

После команды обновите страницу репозитория — там должны появиться файлы.

## Шаг 3. Запустите Render

1. Зайдите на [render.com](https://render.com) и нажмите **Get Started**.
2. Выберите **Sign up with GitHub** и разрешите доступ к репозиториям.
3. В панели Render нажмите **New +** → **Blueprint**.
4. Подключите GitHub и выберите репозиторий `kpk-schedule`.
5. Render сам прочитает файл `render.yaml` и предложит создать сервис
   `kpk-schedule` на плане **Free**.
6. Нажмите **Apply** / **Create** и подождите 2–3 минуты.

Если Blueprint не сработал, создайте сервис вручную:
**New +** → **Web Service** → выберите репозиторий, затем укажите:

| Параметр | Значение |
| --- | --- |
| Runtime | Node |
| Build Command | `npm install --omit=dev` |
| Start Command | `node server.js` |
| Plan | Free |
| Health Check Path | `/api/health` |
| Environment Variable | `HOST` = `0.0.0.0` |

## Шаг 4. Получите ссылку

После деплоя Render покажет адрес вида:

```
https://kpk-schedule.onrender.com
```

Откройте его на телефоне и отправьте друзьям. Ссылка работает без вашего ПК.
Проверить, что сервер жив, можно по адресу
`https://kpk-schedule.onrender.com/api/health` — там должно быть `{"ok":true}`.

## Важно про бесплатный план Render

- Бесплатный сервис **засыпает после 15 минут без запросов**. Первое открытие
  после сна может занять **30–60 секунд** — это нормально, дальше сайт работает быстро.
- В бесплатном плане **750 часов в месяц** на все сервисы. Один круглосуточно
  работающий сервис укладывается в этот лимит (~730 часов).
- Если хотите, чтобы сайт не засыпал, заведите бесплатный монитор на
  [UptimeRobot](https://uptimerobot.com): тип **HTTP(s)**, адрес
  `https://kpk-schedule.onrender.com/api/health`, интервал 10 минут.
  Это не гарантия от перезапусков, но обычно помогает.
- Файловая система на бесплатном плане временная: данные, обновлённые во время
  работы, сбрасываются при перезапуске. Это не страшно — исходные данные лежат
  в репозитории, а расписание всё равно запрашивается с сайта колледжа заново.

## Как обновлять сайт

- **Расписание и преподаватели** обновляются сами: расписание — раз в 2 минуты,
  справочник — раз в 6 часов.
- **Код и оформление**: измените файлы, затем

  ```powershell
  git add .
  git commit -m "Обновил сайт"
  git push
  ```

  Render автоматически пересоберёт и перезапустит сервис.

## Если Render недоступен

Подойдёт любой хостинг, который умеет запускать Docker или Node.js:
**Koyeb**, **Fly.io**, **Railway** (там могут требоваться карта или платный план).
В проекте уже есть `Dockerfile`:

```bash
docker build -t kpk-schedule .
docker run -p 8080:8080 -e HOST=0.0.0.0 kpk-schedule
```

Сайт будет доступен на `http://localhost:8080`.

## Что не нужно делать

- Не коммитьте пароли, токены и ключи — в проекте их нет.
- Не создавайте несколько бесплатных сервисов Render «на всякий случай»:
  часы общего лимита расходуются на все сервисы сразу.
- Не рассчитывайте на мгновенный первый запуск после долгого простоя —
  это ограничение бесплатного тарифа, а не ошибка сайта.
